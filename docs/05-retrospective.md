# 05 复盘

## 实际用时

- 本轮 AI 执行从方案修订到 fixture + 2 条 live 闭环约 70 分钟（含方案审查修订；不含人工复核）。
- 候选人实际投入时间、live 调试时间需自行补充。
- 未完成部分：真实模型稳定性评估、真实 TTS。

## 最难的问题

1. **“真 ReAct”与可测试性的冲突**
   - 固定流程容易测试，但不满足题目；
   - 完全自由 ReAct 不稳定，容易跳过检查。
   - 处理：模型选动作，编排器只做预算和完成闸门；fixture 只证明流程，live 单独标注。

2. **示例数字与工具不一致**
   - 第一版文档的 28 秒示例按公式只有 19.8 秒；
   - 处理：按公式重算旁白/字幕，示例改为 4.2/4.9/5.8/6.3/6.8，并加自洽测试。

3. **检查结果被旧稿复用**
   - 处理：每个 check 绑定 `revision + draft_hash`，闸门比较 hash。

4. **事实夹带**
   - “支持字幕”很容易被扩写成“自动生成字幕”；
   - 处理：claim ledger + 原文 quote + claim 必须出现在分镜 + product scope 也不能豁免额外句子。

5. **评审发现的“证据不扎实”问题**
   - 工具调用上限写了但永远触发不了（每步最多一次工具调用，20 步 < 24 次）；
   - fixture 05 重复写同一份稿，rationale 却写“再压缩一版”，Trace 与事实不符；
   - 多数必选场景只有 fixture 证据，而 fixture 是手写分支，不能证明模型决策。
   - 处理：上限改为 16 并加可触发场景；05 改为真实压缩 + 用规则数据算下限；补 4 条 live；模型 prompt 加入规则集、动作历史和估算公式，让模型能自己算出“理论下限已超目标”（05-live 确实这样做了）。

6. **脚本“太简单”，视频模型照着做不出来**
   - 用户用带角色设定、5 段结构和视觉规范的输入跑 live，结果只有泛泛建议；
   - 根因不在模型：输入规范化和 prompt 用的是字段白名单，创作方向全被丢掉；分镜 schema 没有制作字段；引用检查把“提升”本身当效果数字，主题里的“提升信息密度”被拒；
   - 处理：`creative_brief` 透传、制作字段 + 确定性 `check_production` 进闸门、模型按需读取的写作技能包、`storyboard.md` 交付格式、收窄效果数字判断。

7. **目标脚本的精度远超当前格式**
   - 用户给出 POV 搞笑短剧的目标：多人对白、画外音、带时间的音效、动画屏幕文字、变速、角色状态延续；
   - 按原设计它在入口就失败（JSON 语法、大写键名、白名单丢字段、素材为空、强制产品 claim），写出来也放不下这些信息，英文台词时长也算不准；
   - 处理（阶段 0–2）：输入报错与键名归一、`format`、`fiction`、脚本 v2 字段、按语言和结构计时、逐段计时进 `strict` 格式的闸门。后续阶段见 [06-roadmap.md](06-roadmap.md)。

8. **闸门全过 ≠ brief 被落实**
   - live 14 的稿子通过了全部检查，却漏掉多条用户要求、改了语言；
   - 处理（阶段 3）：`check_brief` 给每条要求一个 id，要求草稿显式声明“哪一镜落实了哪条”，并用原文锚点核对；台词改动必须记录原因；角色和时间线做连贯性检查。
   - 实现中又出现一次“静默丢字段”：fixture 的写稿动作没有带上 `fulfills`/`waivers`/`deviations`。改为 `src/schemas.py` 的 `DRAFT_KEYS` 一处定义、两边共用。

## 学习收获

- Agent 项目的核心不是“让模型写”，而是把工具结果变成下一轮决策的输入；
- 确定性工具是事实和度量的锚点；
- 失败状态、预算、Trace 和测试，比多一个 Agent/框架更能提升可信度；
- 诚实地标注 mock/live 边界，比伪造一条 live trace 更重要；
- fixture 的 rationale 也要引用真实 observation，否则 Trace 会“说一套做一套”；
- 模型只能据它看得到的信息决策：规则集不进 prompt，模型就只能撞上 BR-03 才知道有免责声明要求。
- 输入白名单会静默丢字段：用户多给的信息没有报错也没有进 prompt，排查时先看模型实际收到了什么；
- “写得详细”要落到可检查的字段上，再交给闸门，否则模型没有改稿的依据。
- 只要检查用的是可计算的代理指标（这里是词重合），模型就会朝指标优化：live 14-p3 把 brief 原句抄进画面描述来过检查。代理指标要配一致性检查和人工复核项，不能单独当作完成条件；
- 同一类“静默丢字段”会反复出现（这次是 fixture 的 `write_draft` 丢了 `audio_tracks`，被 `BGM_MISSING` 抓到）：任何透传都要有检查兜底。
